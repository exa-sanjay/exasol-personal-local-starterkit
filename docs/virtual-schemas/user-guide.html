Connecting external sources

Query PostgreSQL, MySQL, SQL Server, Oracle, Exasol, MongoDB, Iceberg lakehouses and Databricks live from your local Exasol, without copying any data. What to enter, where to find it, and samples that work.

How it works inside: Virtual schemas architecture.

1. Before you start

  • The kit is installed and the database runs. Check with exakit status; start it with exakit start.
  • You have a user at the source that can read the tables you want. A read-only user is best. Each source section below lists the minimum rights.
  • The source accepts connections from your machine. For a cloud database, add your public IP to its firewall or security group (see the FAQ).
  • The first source of a kind may restart the database once, to install the runtime its adapter needs (Java for databases, a Rust runtime for MongoDB and the lakehouse). The kit asks first. It takes a minute or two, and later connects of that kind need no restart.

2. How a connect works

One command does everything: it downloads and verifies the adapter (and a JDBC driver where needed), creates a connection that holds the credentials, creates the virtual schema VS_NAME, and proves the link by reading real rows.

Three ways to give the details

WayUse it whenExample
Wizardyou are at a terminalexakit connect, then answer the questions
Flagsyou know the valuesexakit connect postgresql --name sales --url ... --user reader --password-file pg.pw
Environment variablesscripts, CI, AI agents (no terminal)EXAKIT_VS_SOURCE=postgresql EXAKIT_VS_NAME=sales ... exakit connect --json

All three can be mixed: anything not given is asked for (in a terminal) or refused with a clear message (without one).

The connection string

The wizard's first question takes any of these, so you can paste what the cloud console shows:

  • a JDBC URL: jdbc:postgresql://db.example.com:5432/shop
  • a URI: postgres://reader@db.example.com/shop, mongodb+srv://reader@cluster0.abc.mongodb.net/
  • a bare endpoint: db.example.com:5432/shop (as AWS RDS shows it)
  • or press Enter to type host, port and database separately.
Passwords never go on the command line. There is no --password option, and a password inside a pasted URL is removed and not used. Use the hidden prompt, --password-file PATH or --password-stdin.

Where the connection starts

The source is reached from inside the database container, not from your terminal. Two consequences:

  • localhost or 127.0.0.1 for a source on this machine (a local container, say) is handled for you: the kit uses the container's host alias.
  • A cloud source sees your machine's public IP. That's the address to allow in its firewall.

4. Sources

PostgreSQL available Java

Also for Amazon RDS / Aurora PostgreSQL, Azure Database for PostgreSQL, Google Cloud SQL, Supabase, Neon. Command: exakit connect postgresql (aliases pg, postgres).

Parameters

FieldRequiredDefaultExample
Hostyesdb.example.com
Port5432
Databaseyesshop
User / passwordyesreader
Schemayespublicsales

Where to find it

AWS RDS: RDS console, Databases, your instance, Connectivity & security: Endpoint and Port. The instance must be Publicly accessible, and its security group needs an inbound rule for port 5432 from your public IP.

Minimum rights at the source

GRANT CONNECT ON DATABASE shop TO reader;
GRANT USAGE ON SCHEMA sales TO reader;
GRANT SELECT ON ALL TABLES IN SCHEMA sales TO reader;
ALTER DEFAULT PRIVILEGES IN SCHEMA sales GRANT SELECT ON TABLES TO reader;

Sample

PowerShell

exakit connect postgresql --name sales `
  --url "jdbc:postgresql://mydb.abc123.eu-west-1.rds.amazonaws.com:5432/shop" `
  --user reader --schema sales --password-file "$env:USERPROFILE\pg.pw"

bash / zsh

exakit connect postgresql --name sales \
  --url "jdbc:postgresql://mydb.abc123.eu-west-1.rds.amazonaws.com:5432/shop" \
  --user reader --schema sales --password-file ~/pg.pw
exakit sql 'SELECT * FROM VS_SALES."orders" LIMIT 10'

Good to know

  • Names keep their PostgreSQL spelling (usually lower case): quote them, e.g. "orders". From PowerShell, escape the quotes inside single quotes as \"orders\".
  • NUMERIC arrives as VARCHAR (it can exceed Exasol's DECIMAL range), TIMESTAMPTZ as TIMESTAMP, and JSON, UUID and INTERVAL as VARCHAR. CAST before you aggregate.
  • Array columns are left out, and BYTEA reads as the text bytea NOT SUPPORTED.

MongoDB / Atlas available Rust

MongoDB Atlas, self-hosted MongoDB, a local container. One collection per source. Command: exakit connect mongodb (alias mongo).

Parameters

FieldEnv variableRequiredDefaultExample
HostEXAKIT_VS_HOSTyescluster0.abc12.mongodb.net
PortEXAKIT_VS_PORT27017(none for mongodb+srv://)
User / passwordyesa user defined in the admin database
DatabaseEXAKIT_VS_DATABASEyessample_mflix
CollectionEXAKIT_VS_COLLECTIONyesmovies

Where to find it (Atlas)

  1. Connection string: Clusters, Connect, Drivers. Copy the mongodb+srv://... string, and remove the :<db_password> part.
  2. User: Security, Database Access, add a user with password authentication and the role Only read any database (or read on one database). Atlas creates users in admin, which is what the adapter needs.
  3. Network: Security, Network Access, Add Current IP Address. Avoid temporary entries: when they expire, the source stops working.

Minimum rights (self-hosted)

use admin
db.createUser({ user: "reader", pwd: passwordPrompt(), roles: [ { role: "read", db: "shop" } ] })

Sample

PowerShell

$env:EXAKIT_VS_DATABASE = "sample_mflix"
$env:EXAKIT_VS_COLLECTION = "movies"
exakit connect mongodb --name movies --url "mongodb+srv://reader@cluster0.abc12.mongodb.net/" `
  --password-file "$env:USERPROFILE\atlas.pw"

bash / zsh

EXAKIT_VS_DATABASE=sample_mflix EXAKIT_VS_COLLECTION=movies \
exakit connect mongodb --name movies --url "mongodb+srv://reader@cluster0.abc12.mongodb.net/" \
  --password-file ~/atlas.pw
exakit source describe movies                                  # see the tables it made
exakit sql 'SELECT "title", "year" FROM VS_MOVIES."MOVIES" LIMIT 10'

How documents become tables

  • The documents form a root table; MongoDB's _id is the column mongo_id.
  • A nested object becomes a child table, joined on root."field|object" = child."_id".
  • An array becomes a child table joined on "_parent", ordered by "_pos".
  • Fields and child tables keep MongoDB's spelling: quote them.
  • Columns are inferred from a sample of up to 100 documents. After the collection's shape changes, run exakit source refresh NAME.
-- a nested object as columns (check the exact child table names with: exakit source describe NAME)
SELECT t."theaterId", l.*
FROM VS_THEATERS."THEATERS" t
JOIN VS_THEATERS."THEATERS_location" l ON t."location|object" = l."_id";

Good to know

  • The adapter always logs in against the admin database, whatever the URI says. A different authSource is refused up front.
  • Give one host (or a mongodb+srv:// name), not a list of hosts: the driver finds the other members itself.
  • TLS is verified. --tls none only for a MongoDB on this machine or a private network.
  • A refused login and a TLS mismatch produce the same message from the adapter. The kit lists both to check.

What Databricks must allow (setups B and C)

  1. The schema lives on your own cloud storage (an external location, and a schema with MANAGED LOCATION). Databricks Default Storage (Free Edition, serverless-only workspaces) is never readable from outside.
  2. External data access is on for the metastore (Catalog, the gear icon, Metastore).
  3. The token's user has the grants: 
    GRANT USE CATALOG ON CATALOG workspace TO `user@example.com`;
GRANT USE SCHEMA, EXTERNAL USE SCHEMA, SELECT ON SCHEMA workspace.sales TO `user@example.com`;

Good to know

  • Table and column names arrive upper-cased (ORDERS, ORDER_ID): query them without quotes.
  • Not read: Iceberg tables with equality deletes, and ORC or Avro data files. Positional deletes and deletion vectors are read.
  • A Databricks Delta table whose newest commits live in Unity Catalog ("catalog-managed") can't be read on route C yet. Use route B or the Databricks connector.
  • The kit's catalog types are Iceberg REST (token or keys) and Unity. AWS Glue's and S3 Tables' REST endpoints need SigV4 signing, which the kit doesn't offer yet.

  --url 'jdbc:databricks://dbc-a1b2c3d4-e5f6.cloud.databricks.com:443/default;transportMode=http;ssl=1;AuthMech=3;httpPath=/sql/1.0/warehouses/abc123def456;' \

Good to know

  • The shared samples catalog lists no tables this way. Use a schema of your own.
  • Upstream limits: at most 50 tables per virtual schema, BINARY columns not supported, no TABLE_FILTER.
  • The adapter's metadata calls are pinned to the workspace certificate. When Databricks renews it, exakit source check NAME verifies and pins the new one.
  • Rows, and the token with them, travel encrypted but without certificate verification. Give this source a token of its own, scoped as narrowly as the workspace allows.
  • To avoid warehouse costs for Iceberg or Delta tables on your own storage, see the lakehouse routes B and C.

Snowflake not available yet

Listed, but refused: the Snowflake driver always verifies the server's certificate, and Exasol Personal's import process has no trust store to verify it with yet. EXAKIT_VS_ALLOW_UNAVAILABLE=1 lets you try it (for example on a newer Exasol Personal). For when it works: account URL host, warehouse, database, schema, an optional role, and a service user with a programmatic access token as the password.

Querying tips

  • Quoting: PostgreSQL, MySQL, SQL Server and MongoDB keep their names' spelling: quote them. Oracle, Snowflake and the lakehouse arrive upper case: no quotes needed.
  • PowerShell: inside single quotes, write \"orders\" for a quoted name: exakit sql 'SELECT * FROM VS_SALES.\"orders\"'.
  • Joins across sources work like any join: SELECT ... FROM VS_SALES."orders" o JOIN TPCH.CUSTOMER c ON ....
  • What runs at the source: EXPLAIN VIRTUAL SELECT ... shows the statement the adapter sends, so you can see whether a filter or aggregate was pushed down.
  • A local copy for heavy repeated queries: CREATE TABLE MYCOPY.ORDERS AS SELECT * FROM VS_SALES."orders";
  • AI clients connected over MCP can query VS_NAME straight away, as the read-only MCP user.

7. FAQ

Basics

Is my data copied into Exasol?

No. Every query reads the source live. Only metadata (table and column names) is stored in the virtual schema; exakit source refresh re-reads it. If you want a copy, make one: CREATE TABLE ... AS SELECT * FROM VS_NAME.T.

How fast is it, and what does it cost at the source?

Filters, projections, LIMIT and (for most sources) aggregates are pushed to the source, so only matching rows travel. The source does that work: for Databricks via a SQL warehouse, that's billed warehouse compute. The lakehouse routes read files directly and use no compute at the source. Check what was pushed down with EXPLAIN VIRTUAL.

Can I join tables from different sources?

Yes. A virtual schema is a schema like any other: join VS_SALES with VS_MOVIES or with local tables in one query.

Can I connect several schemas of one database?

Yes, one source per schema: exakit connect postgresql --name sales_eu --schema eu ... and --name sales_us --schema us .... They share the downloaded adapter and driver.

Can I write to the source?

No. Virtual schemas are read-only.

Security

Where is my password stored? Can I see it again?

Only inside the database's CONNECTION object EXAKIT_SRC_NAME. It is never in the kit's files, logs or JSON output, and the kit can't show it again. To change it, use exakit source reauth NAME.

Why is there no --password option?

A command line is visible to every process on the machine and lands in shell history. Use the hidden prompt, --password-file or --password-stdin. A password inside a pasted URL is removed and not used.

"Encrypted, certificate not verified": is that safe?

The traffic is encrypted, so it can't be read in passing. But without verifying the certificate, a machine that intercepts the connection could pretend to be the source. Exasol Personal's import process has no trust store yet, which is why the JDBC sources can't verify. Use those sources over networks you trust. Exasol (pinned fingerprint), MongoDB and the lakehouse (public CAs) are verified.

Can my AI assistant see the external data?

Yes: the read-only MCP user can read every schema, virtual ones included, and the kit says so after a connect. It can only read; it never sees the credentials. To take a source away from AI clients, remove the source.

Connecting

My cloud database times out, but my SQL tool on the same PC connects fine.

Usually the firewall. A cloud database sees your machine's public IP; check it with curl https://api.ipify.org and allow it:

  • AWS RDS: the instance's security group, inbound rule, the port (5432, 3306 ...), source My IP. The instance must be Publicly accessible.
  • Azure SQL / PostgreSQL / MySQL: the server's Networking page, add a firewall rule.
  • MongoDB Atlas: Security, Network Access, Add Current IP Address (not a temporary entry).

Also: on a VPN that doesn't route the container's traffic, the database may not reach a company-network source even when your PC does.

My source runs on my own machine (a container). Which host do I give?

localhost and the published port. The kit rewrites it to the container's host alias, because localhost inside the database is the database itself.

Why does the first connect restart the database?

The adapter needs a script runtime inside the database: Java for the JDBC sources, a pinned Rust runtime for MongoDB and the lakehouse. Installing one takes effect only on a restart. The kit asks first, it happens once per runtime, and Lua (Databricks) needs none.

Can I script it, or let an AI agent do it?

Yes: flags or EXAKIT_VS_* variables, a password file, --yes for the restart consent, and --json for one machine-readable answer. Without a terminal the kit never prompts; it refuses with a message saying what is missing.

Using it

A table I just created at the source doesn't show up.

Run exakit source refresh NAME. The table list is read when the virtual schema is created or refreshed. (MongoDB: also after the collection's document shape changes.)

"object not found", but the table exists.

Usually case. PostgreSQL, MySQL, SQL Server and MongoDB names keep their spelling: "orders", not ORDERS. exakit source describe NAME shows the exact names.

The source password or token changed, or expired.

exakit source reauth NAME --password-file PATH. The new credentials are tested on a staging connection first; the old ones stay until the new ones work. Databricks tokens expire at the lifetime you chose when creating them.

Everything stopped working after a PC restart.

Start the database (exakit start), then run exakit source check NAME: it repairs what a restart can undo, such as name resolution inside the database.

The samples catalog shows no tables.

It's a shared catalog that the Unity Catalog API doesn't list. Create a table in a schema of your own (e.g. CREATE TABLE workspace.default.orders AS SELECT * FROM samples.tpch.orders LIMIT 1000) and connect that schema.

I can't find where to create an access token.

It's under your user settings, not workspace admin: profile icon, Settings, Developer, Access tokens. If it's missing, a workspace admin has turned personal access tokens off.

Removing

How do I remove a source completely?

exakit source remove NAME --dry-run lists what would go, then --yes removes it: the virtual schema, the connection, and the adapter, driver and files no other source still uses. Only objects the kit created are ever dropped. Before uninstalling the kit, remove its sources this way; exakit uninstall --dry-run shows what an uninstall would take.

Why isn't Snowflake available?

Its driver always verifies certificates, and Exasol Personal's import process has no trust store yet, so it can't read data. It becomes available when Exasol Personal ships one.
